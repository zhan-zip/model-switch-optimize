# 内置诊断规则库（开发者维护，随程序发布）

> 供决策模型 conclude_diagnosis 使用：结合四项检查事实，按以下要点判断故障原因并给出建议动作。
> 使用者不接触本文件；后期高频场景将固化为程序直判。

## 错误类别速查

- **401（鉴权失败）**：key 无效、被吊销、或与分组不匹配。建议：换 key / 换同服务商其他分组 / 检查 key 所属分组。
- **429（限流）**：请求过快或余额耗尽。建议：稍后重试 / 充值 / 换分组。若四项检查中余额不足，优先充值或换分组。
- **5xx（服务端故障）**：服务商内部错误。建议：等修复 / 换其他服务商分组。
- **timeout（超时）**：网络不通、代理问题或服务端响应慢。建议：检查本地网络与代理 / 换线路。
- **network（断网/DNS）**：本地网络问题。建议：检查本地网络连通性。

## 特殊错误形态

- **HTTP 403 + error 1010**：网关 UA 拦截（非 key 问题）。建议：检查客户端 User-Agent 是否被网关拦截，与 key 无关，勿盲目换 key。
- **HTTP 403 + channel:codex_only**：该分组为专用通道，仅特定官方客户端可用。建议：换普通分组，该分组本身无故障。（注：2026-09-28 实机复验当前环境未复现该错误码——服务端通道策略变化，本规则仍基于错误特征保留有效）

## 判断顺序

1. 先看四项事实：网站可达 / 余额 / key 分组 / 模型连通——事实优先于猜测。
2. 网站不可达 → 网络或服务商故障，等修复或换服务商。
3. 网站可达但连通失败 → 按错误类别速查定位（key / 余额 / 分组 / 模型）。
4. 结论须给出：一句话原因 + 1~3 个可执行建议动作（充钱 / 换分组 / 换 key / 等修复）。
5. 无法确定时如实说明，建议用户在控制台核实，不编造结论。
