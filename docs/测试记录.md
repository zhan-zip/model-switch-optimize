### 真机连通测试（真实模型，每分组一个代表模型）

环境变量设置 6 个 key（KEY_YYAPI_K3 / KEY_YYAPI_K2 / KEY_ROUTER4_GIFT / KEY_ROUTER4_GEM / KEY_ROUTER4_PRO / KEY_DEEPSEEK），`mso validate` 通过（服务商 3 · 分组 6 · 模型 36 · 保底 deepseek/official/deepseek-chat）。

| 分组 / 代表模型 | 结果 | 备注 |
| --- | --- | --- |
| yyapi/kiro-3/claude-sonnet-5 | ✓ 2381ms tokens=69 | 首测 403(Cloudflare 1010)，加 User-Agent 后通过 |
| yyapi/kiro-2/claude-sonnet-5 | ✓ 3356ms tokens=69 | 同上 |
| router4/GeminiApi/gemini-3.5-flash | ✓ 1392ms tokens=7 | 一次通过 |
| router4/GptPro/codex-auto-review | ✓ 1997ms tokens=12 | 一次通过 |
| deepseek/official/deepseek-chat | ✓ 552ms tokens=7 | 一次通过 |
| router4/gift/gpt-5.5（及 codex-auto-review） | ✗ 403 channel:codex_only | **该分组为 Codex 专用通道**，仅服务官方 Codex 客户端，普通 API 调用被拒——通道本身限制，非本模块缺陷；已列为诊断场景素材 |

真机修复：client.py 增加自定义 `User-Agent` 头（部分网关/Cloudflare 拦截默认 urllib UA，返回 403 error 1010）。

事件流落盘验证：每次 `mso tools --check` 在 `data/events/<trace_id>.jsonl` 留痕（model_called → model_responded / model_failed，cause 追溯链完整）。

### 结论

阶段2 验收通过：六工具齐备（call_model / list_models / test_connectivity / console_check / web_search / fault_history）+ 统一 dispatch 分发；mock 三件套可无 key 跑通；真机 5/6 分组真实连通，1 个分组为服务端通道限制（已识别、已记录）；74 用例全绿。
